# Fluxbase Documentation Site

The docs live in a [Starlight](https://starlight.astro.build/) (Astro) site.
~120 pages are handwritten under `src/content/docs/`; the API reference under
`src/content/docs/api/` is generated from the SDKs.

## Working on the docs

```bash
make docs               # serve at http://localhost:4321 (hot reload)
make docs-build         # production build (also the CI check)
make docs-check-links   # build + lychee link check
make sdk-kotlin-docs    # regenerate Kotlin SDK API docs (Dokka GFM)
```

You can also use the package scripts directly from this directory
(`npm run dev`, `npm run build`).

## Layout

- `src/content/docs/getting-started/` — quick start, intro, building from source
- `src/content/docs/guides/` — feature guides (auth, storage, AI, MCP, …)
- `src/content/docs/reference/` — configuration reference, cookbook, comparisons
- `src/content/docs/security/` — security guides
- `src/content/docs/deployment/` — Docker/Kubernetes/scaling
- `src/content/docs/cli/` — CLI reference
- `src/content/docs/about/` — pricing, AI transparency

## Generated API reference

The TypeScript SDK references (`src/content/docs/api/sdk*`) are produced by
typedoc via `starlight-typedoc` during the docs build; the Kotlin reference
is pre-generated by `make sdk-kotlin-docs` (Dokka GFM) and committed. Don't
hand-edit generated pages.

## CI

The `Docker Docs Build Test` job in `.github/workflows/ci.yml` builds the
site, runs the lychee link checker (config in `.lychee.toml`), and builds the
`Dockerfile.docs` image. Broken links and build failures fail CI — run
`make docs-check-links` before pushing doc changes.
